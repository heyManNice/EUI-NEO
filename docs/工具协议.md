# 工具协议

调试面板（`modules/devtools`）及其他外部工具（Profiler、HUD、MCP 智能体）需要观察框架内部状态：元素树、属性、命中结果、渲染变换、性能指标与视口图像，并且能把修改临时写回运行时。本文说明工具接缝（Tooling Seam）的职责边界、生命周期时序与接入约定。

核心目标是让框架不再因为诊断工具而分化分支。新增一类数据源只需在工具侧实现展示或分发逻辑，不需要在核心代码中反复插入条件编译。

## 核心原则

- 能力归核心，策略归模块：核心提供只读感知、像素回读、动作调度与生命周期切入点；展示样式、属性编排、快照序列化、短句柄生成和协议转换均留在模块侧。
- 复杂度留在工具侧：框架核心保持精简、零分支与零虚函数膨胀；工具模块承担数据编排、拷贝节流和状态管理。
- Release 构建零开销与零符号残留：接缝由统一开关 `EUI_TOOLING` 控制。未开启时钩子内联为空操作，生产构建不导出任何工具符号。

## 协议模型

接缝模型抽象为四个操作动词与帧驱动流程：

```text
Snapshot   枚举数据源：元素树、状态实例、输入事件流、重绘原因、性能度量
Resolve    按 ID 或命中点查询几何：Frame、Transform、Clip、盒模型
Control    临时写入：属性补丁、清除覆盖、触发重绘与输入注入
Frame      宿主帧驱动：beginFrame -> compose -> afterCompose -> render -> drawOverlay
```

数据源与核心接口映射：

- Elements / Layout：`elementRoots()`、`findElement(id)`、盒模型与裁剪几何。
- Performance：`PerformanceSnapshot` 采样数据。
- State：`InstanceStore` 实例表只读枚举。
- Input：最近事件队列采样与命中路由。
- MCP / Automation：`readFramebufferPixels()` 像素回读、`frameSequence` 帧同步、文本无障碍快照与键盘/输入注入。
- Frames：重绘原因与脏区标记。
- Scale：DPI、PointerScale 与 UIScale 度量。

## 职责划分

核心只读接缝（`core/tooling/`）：

- `config.h`：统一门控判定（`EUI_TOOLING` 到 `EUI_TOOLING_ENABLED`）。
- `model.h`：几何模型（`ElementBox` 盒模型、`ElementMark` 标记）。
- `inspect.h`：元素查找与盒模型测量。
- `state.h`：`ToolingState` 运行时状态槽与世代计数。
- `hooks.h`：生命周期钩子（`beforeCompose`、`afterCompose`、`drawPassOverlay`）。
- `pass.h`：渲染过程上下文 `RenderPassContext`。

应用接入面（`include/eui/detail/overlay_hooks.h`）：

- `OverlayHooks`：工具实现挂载与应用主循环调度。
- `OverlayWindows`：多窗口管理与悬浮停靠支持。

调试模块私有实现（`modules/devtools/`）：

- `fields.{h,cpp}`：属性反射字典、补丁存储与写回。
- `tree.{h,cpp}`：元素树快照抓取与平铺映射。
- `preview.{h,cpp}`：盒模型高亮与轮廓线渲染。
- `mcp_*.{h,cpp}`：MCP 协议服务（JSON-RPC / HTTP）、文本 a11y 快照、动作执行与 2 帧同步。
- `mcp_bridge/`：零依赖 Python Stdio 桥接、直接 CLI 驱动与进程守护。

## 生命周期时序

核心在执行流程中仅调用无条件内联钩子，不包含具体的工具分支：

```text
页面更新阶段：
  tooling::beforeCompose(runtime)     -> 世代计数递增，重置缓存
  composeFn(ui, screen)               -> 应用构建新元素树
  ui.end()
  tooling::afterCompose(runtime)      -> 回放工具注册的补丁（在 Layout 前写回活元素）
  ui.layout(...)                      -> 执行几何测量与排版

渲染阶段：
  页面普通渲染...
  tooling::drawPassOverlay(...)       -> 工具在当前裁剪空间下绘制高亮覆盖
  tooling::drawOverlay(...)           -> 独立视口/停靠图层绘制
```

- afterCompose 回调：核心提供树刚生成完毕、布局尚未发生的时间窗口。工具将补丁写回挂载在此处，使临时覆写的属性随新树一同生效，且不污染应用源状态。
- 输入过滤机制：工具通过 `Runtime::setInputFilter` 接管命中测试，元素拾取操作优先被工具消费，不触发页面原有事件。
- 帧同步机制：MCP 动作注入后通过 `waitForFrame(targetSeq)` 等待至少两帧渲染与重组完成，消除异步竞态。

## 属性字段表驱动

为保证属性扩展的可维护性，字段映射收敛在 `modules/devtools/fields.h` 的 X-Macro 表中：

```cpp
#define DEVTOOLS_ELEMENT_FIELD_TABLE(X)               \
    X(Color,           Color,  color)                 \
    X(Opacity,         Number, opacity)               \
    X(Radius,          Number, radius)                \
    X(BorderWidth,     Number, border.width)          \
    ...
```

扩展一个可编辑属性只需：

1. 在 `fields.h` 的 `DEVTOOLS_ELEMENT_FIELD_TABLE` 增加一行。
2. 在 `properties.cpp` 的 `propertyDescriptors()` 增加展示元数据。
3. 核心代码零修改：读写、校验、补丁存储与 UI 控件分发均自动展开。

## 约束与反模式

- 只传递计算结果，不暴露内部容器：核心计算完毕后以只读结构交付，不将内部的 `std::vector` 或 map 直接暴露给外部。
- 单一数据流：工具直接通过绑定的 `Runtime` 接口单向读取与注册，不建立多层虚代理转发。
- 禁止为单一工具定制核心回调：新需求收敛在通用数据源（Snapshot）或统一几何解析（Resolve）中。
- 禁止在核心层实现字符串反射：保持静态编译期代码生成，不为 Element 引入动态虚派发和运行时字典寻址。
- 禁止工具代码污染 Release 发行版：工具实现全部留在 `modules/devtools` 内，关闭 `EUI_TOOLING` 时保持零开销。

## 验证方式

```sh
# 核心运行时不存在工具业务标识
grep -rn "ElementField\|ElementPatch\|ElementValues" core include

# Release 构建不导出工具符号
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --target eui_neo
llvm-nm --defined-only build-release/lib*eui_neo*.a | grep -cE "DevtoolsHost|ElementPatches"

# 单元测试覆盖
ctest --test-dir build -R "devtools|runtime_inspection" --output-on-failure
```
